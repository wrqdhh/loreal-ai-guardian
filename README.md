# 信任守护师 · 内容核验 Agent

**TrustGuardian** — 面向 UGC 美妆种草内容的多模态真伪核验与合规审查 Agent

> 天池·欧莱雅第二届美妆科技黑客松 · 赛题二
> **「信任守护师 —— 创造者的 AI 卫士」**

给一条「图片 + 文案 + 评论区」的种草内容，输出四件事：**真伪判定、可疑位置标注、逐条判定依据、可执行的处置建议**——并且把核验的每一步完整摊开给人看。

```
输入（图文 + 评论）→ 多模态取证 → 证据归因 → 风险定级 → 处置建议
                          ↑                              ↓
                     7 步工具链全程留痕 ───────────────────┘
```

## 快速开始

**不需要 `npm install`，不需要后端，不需要 GPU，断网可跑。**

```bash
# 方式一：直接双击 index.html（file:// 协议即可）

# 方式二：起一个本地静态服务（推荐，行为更接近线上）
python -m http.server 8000
# 然后打开 http://127.0.0.1:8000/index.html
```

要求 Chrome / Edge 90+。所有计算在浏览器内完成，**上传的图片不会离开本机**。

### 三个内置对照样本

点右上角「载入示例」即可生成三组程序化构造的样本，无需准备素材：

| 样本 | 构造方式 | 预期结论 |
|---|---|---|
| `ai` | AI 生成质地的产品图 + 模板化文案 + 组织化刷评 | 极高风险 |
| `splice` | 真实底图上拼接/替换区块 + 与画面色系冲突的文案 | 高风险 |
| `clean` | 一致的手持实拍 + 真人写作风格的文案 | 低风险（对照组） |

深链接可直接打开并自动核验：

```
index.html#sample=ai       # 或 splice / clean
index.html#selfcheck       # 自动跑完三组样本的内置回归自检
```

## 系统架构

```
index.html      页面结构与样式（无构建、无框架）
├── engine.js   取证引擎：像素级信号提取 + 文本统计/词表
├── agent.js    Agent 编排：7 步工具链、证据融合、定级、处置映射
├── samples.js  程序化构造三组对照样本（便于零素材演示）
└── app.js      界面渲染、画布叠加、轨迹可视化

selftest.js     Node 侧逻辑自检（22 项断言，不依赖浏览器）
```

**分层原则**：`engine.js` 只回答「图上/文里有什么异常信号」，不做价值判断；`agent.js` 负责「这些信号意味着什么、该怎么办」。两层解耦，取证算法可单独替换成训练好的模型。

## 检测方法

### 图像取证（5 个检测器 + 元数据溯源）

| 判据 | 算法依据 | 能检出什么 |
|---|---|---|
| ELA 重压缩残差 | 按质量 90 重编码后逐像素求差，分块看响应是否局部异常 | 局部编辑、拼接替换、来自异源的区域 |
| 噪声一致性 | 3×3 中值滤波提取高频残差，逐块比较噪声强度 | 拼接断层、局部磨皮、区块级替换 |
| 色度噪声比 | 比较色度通道与亮度通道的噪声能量比 | 扩散模型生成图（真实传感器有色度噪声） |
| 直方图量化痕迹 | 扫描直方图空洞与峰值离散度 | 重度调色、生成图上采样痕迹 |
| 复制-移动粗检 | 分块哈希匹配查找重复区块 | 内容搬运、背景克隆 |
| 元数据溯源 | 解析 JPEG EXIF / PNG `tEXt` 文本块 | 缺失拍摄信息、Midjourney 等生成管线签名 |

### 文本与评论核验（3 个检测器）

| 判据 | 算法依据 |
|---|---|
| 文体统计与生成倾向 | 句长变异系数、连接词密度、细节缺失度、排比结构、情绪词密度、**不确定性与负面表述缺失度** |
| 广告合规词表扫描 | 绝对化用语 / 医疗功效宣称 / 效果承诺三类词表，命中处正文高亮 |
| 评论区刷评特征 | 评论文本重合度、句式模板化、时间分布、账号表述同质化 |

### 图文交叉核验

把文案中提到的色系与图像主色做对照。**无彩色系（黑白灰）不参与判定**——否则评论里一句「显白」会被画面的白色背景当成匹配项，把真实冲突消解掉。

## Agent 决策闭环

七步工具调用，每步留痕：

| # | 步骤 | 工具 |
|---|---|---|
| 1 | 解析待核验内容 | `content_parser` |
| 2 | 元数据与来源溯源 | `exif_probe` |
| 3 | 多模态图像取证 | `forensics_pipeline` |
| 4 | 文本与评论区核验 | `text_pipeline` |
| 5 | 图文一致性交叉核验 | `cross_modal_check` |
| 6 | 证据聚合与归因 | `evidence_fusion` |
| 7 | 风险定级与处置决策 | `decision_engine` |

**证据融合**采用概率合成而非加权求和——避免「多条弱证据堆出一个高风险」：

```
overall = 1 − (1 − p_image) · (1 − p_text) · (1 − 0.8 · p_cross)
```

单条证据的贡献为 `severity × confidence`；交叉证据按 0.8 折算，因为它依赖前两步的中间结果。

**定级**：≥70 极高风险 · ≥48 高风险 · ≥26 中风险 · <26 低风险

**处置建议**由证据驱动：每条建议都标注触发它的证据 ID，复核时可反向追溯到具体判据，而不是凭空给一句「建议人工复核」。

## 实测结果

在无头浏览器（Edge）中真实跑完整个 UI 链路的结果，**非估算值**：

| 样本 | 得分 | 判定 | 关键证据 |
|---|---|---|---|
| AI 合成素材 | **95** | 极高风险 · 立即处置 | 无 EXIF + 噪声均值 0.24（几乎无传感器噪声）+ 1024×1024 生成常用尺寸 + 生成倾向 0.53 + 违规表述 9 处 + 刷评倾向 1.00 |
| 局部拼接篡改 | **57** | 高风险 · 优先处理 | 低噪声团块 23 块（定位到补丁区）+ ELA 低响应团块 + 图文色系冲突 3 处 |
| 正常内容（对照） | **17** | 低风险 · 常规观察 | 仅「缺失拍摄元数据」一条辅助证据 |

## 工程上的关键取舍

这几条是原型能不能用的分水岭，也是方案里最值得讲的部分：

1. **只看单块阈值必然误报。** 物体轮廓、文字笔画同样产生异常块。改为异常块四连通聚类，再加两个几何判据：**填充率 ≥ 0.45**（真实拼接是实心团块，细线和空心环被剔除）+ **面积占比 ≤ 32%**（排除天空、背景墙等天然平滑的大片区域）。

2. **噪声检测必须加平坦度掩膜。** 中值滤波残差在强边缘处天然偏高。只让局部梯度低于全图中位 2.2 倍的块参与噪声判断。加掩膜前正常样本被判 62 分高风险，加之后降到 17 分。

3. **「合成图 ELA 更均匀」这个直觉是错的。** 实测 AI 图 ELA 均匀度 0.16、正常图 0.91，与预判完全相反。该判据已被删除，改为 ELA 高/低两个方向的团块检测。

4. **文体检测需要「人类证据」抵扣项。** 只设惩罚项时，正常长文案会被误报（0.446 > 阈值 0.42）。补上「缺少不确定性与负面表述」这一项——真人几乎一定会写「不过」「有一点点」「介意的慎入」——正常样本降到 0.383。

5. **画面标注只画真正构成证据的团块。** 早期版本在判定为低风险的图上仍画满红框，判定与画面自相矛盾。现在叠加层只渲染通过几何过滤、且被 Agent 采纳为证据的团块。

## 能力边界

**这是取证级启发式检测，不是训练过的深度伪造分类器。**

- 输出的是「可疑证据」而非「真伪判决」，所有高风险结论都需要人工复核。
- 社交平台转存会剥离 EXIF，重度美颜会同时压低噪声与色度信号——两者都会导致误报。
- 针对新型生成模型（如最新扩散架构）的检出率未经验证；当前阈值是在内置样本上调出来的，**换数据分布需要重新校准**。
- 它的定位是：**把人工复核从全量盲审缩小到定向抽检**，而不是替代人做最终裁决。

页面内「方法学与能力边界」抽屉写明了全部判据的算法依据与上述限制。
