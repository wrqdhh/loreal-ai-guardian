# 系统测试数据（dataset）

本目录对应赛题「题目要求」中的第二项：

> **系统测试数据**：一批由 AI 生成的高仿伪造内容样本（如 AIGC 生成种草文案/图片、虚假评论样本等），用于在选定场景下测试或者评估 Agent。

它是 `benchmark` 的输入，也是把演示型 Demo 变成可量化评测结果的关键。

---

## 目录结构

```
dataset/
├── README.md            本文件
├── manifest.json        图像样本清单（由 tools/make_splices.js 生成）
├── raw/                 素材（不直接参与评测）
│   ├── real/            真实相机照片 —— 负样本来源，必须真人拍摄
│   └── ai/              真实 AIGC 图片 —— 正样本来源，必须来自生成模型
├── samples/             合成后的测试样本
├── masks/               篡改区域的像素级 ground truth（仅篡改类有）
└── text/
    └── text_set.json    文本与评论区样本 + ground truth
```

## 图像样本构成

| 类别 | `category` | `label` | 构造方式 | 用途 |
|---|---|---|---|---|
| 真实原图 | `real_original` | `authentic` | 实拍照片原样 | 测误报（不该报警的别报） |
| 美颜实拍 | `retouched_real` | `authentic` | 实拍 + 局部磨皮 + 提亮 | 测误报（美颜不应被判伪造） |
| AIGC 原图 | `ai_plain` | `ai_generated` | 生成模型原样输出 | 测正检率 |
| 拼接篡改 | `splice_ai_into_real` | `tampered` | 真实底图 + AIGC 贴片（羽化边缘） | 测正检率 + 区域定位 IoU |

**为什么要有「美颜实拍」这一类**：真实平台上的种草图几乎都经过美颜，如果 Agent 把它们一律判为伪造，产品上就不可用。这一类专门用来暴露误报。

**为什么拼接样本要带 mask**：只判断「真假」无法体现「标出可疑之处」这个要求。有了像素级 mask，评测才能计算**定位 IoU**，衡量 Agent 标得准不准，而不只是判得对不对。

### 标注 schema（`manifest.json`）

```json
{
  "id": "splice_0007",
  "image": "samples/splice_0007.png",
  "mask":  "masks/splice_0007.png",
  "category": "splice_ai_into_real",
  "label": "tampered",
  "synthetic": false,
  "width": 900, "height": 700,
  "region": { "x": 312, "y": 188, "w": 260, "h": 210, "shape": "ellipse", "feather": 6 },
  "donor": "ai_wanxiang_03.png"
}
```

- `label`：`authentic` / `ai_generated` / `tampered`
- `synthetic`：**`true` 表示程序化生成的素材，不得计入评测指标**。用 `--demo` 跑出来的样本全是 `true`
- `region` / `mask`：仅篡改类有

## 文本样本 schema（`text/text_set.json`）

```json
{
  "id": "t_human_foundation_05",
  "scene": "种草内容核验",
  "title": "用了快一个月，说说真实感受",
  "body": "……",
  "comments": ["……"],
  "labels": { "ai_written": false, "ad_violation": false, "shill": false }
}
```

三类标签，各自独立，可组合出现（例如 `t_human_adlaw_09` 是真人写的但含违规宣称）。

## 素材怎么准备

### 真实照片（`raw/real/`，**必须真人拍摄**）

这是整套数据集的诚信底线。**AI 生成的图片不能当真实照片用**——否则评测出来的是一个自欺欺人的好数字。

用手机拍 **10–20 张**即可，主题建议覆盖赛题场景：

- 护肤品/化妆品实物（瓶身、膏体、质地特写）
- 手臂或面部试色
- 化妆台、洗手台等真实环境
- 开箱、包装

要求：正常光照、不要过度后期、PNG 格式（JPEG 请先转换）。**不要拍他人正脸**，避免人脸合规问题。

### AIGC 图片（`raw/ai/`）

用任意生成模型产出 **10–20 张**同类主题图：

- 通义万相 / 通义千问（阿里云，300 元代金券可用）
- Stable Diffusion / Midjourney / 文心一格 等

建议故意混入不同风格：写实产品图、种草氛围图、假的「使用前后对比图」——后者正是赛题点名的典型场景。

**生成后请保留原始文件**，不要二次压缩或截图，否则会破坏生成模型的统计特征，让检测变得不真实（或反过来，变得过于容易）。

### 扩充文本样本

当前 `text_set.json` 是 **10 条种子集**，规模只够验证流程，不够支撑正式的精确率/召回率数字。建议扩充到每类 30 条以上。

用大模型批量生成 `ai_written=true` 样本时的提示词模板：

```
请生成 30 条美妆护肤类种草文案，风格要求：
- 句式整齐、多用四字短语与排比
- 大量使用绝对化表述（最、第一、彻底、永久）
- 不写具体使用场景、时间、地点
- 不写任何缺点或不确定性
每条 150-250 字，只输出文案正文，用空行分隔。
```

真人样本（`ai_written=false`）**建议团队成员手写**，每人写 5–10 条。真人写作的特征（犹豫、具体细节、负面表述、口语）目前很难被提示词稳定复现，让模型模仿会产生标签噪声。

## 复现步骤

```bash
# 1) 放入素材
#    dataset/raw/real/*.png   真实照片
#    dataset/raw/ai/*.png     AIGC 图片

# 2) 生成样本与清单
node tools/make_splices.js --seed 42

# 3) 没有素材时，先跑通工具链（产出的样本 synthetic=true，不参与评测）
node tools/make_splices.js --demo

# 4) 跑评测（浏览器端，见项目根目录 README）
```

同一 seed + 同一素材 → 同一份数据集，可在论文/方案里写明可复现。

## 合规与来源

- 真实照片须为**团队成员自行拍摄**，或取得授权的素材；不要爬取社交平台的他人内容。
- 涉及人脸的画面须取得本人同意，或直接使用非人脸题材。
- AIGC 图片请遵守所用生成平台的服务条款。
- 数据集**仅用于本次赛事场景下的测试与评估**，不得用于赛事之外的用途（天池参赛规则第 2 条）。

---

## 已知局限

- 拼接样本的边缘是羽化的矩形/椭圆，与真实 PS 篡改的复杂边界有差距，**检测结果会偏乐观**。
- 美颜干扰类只做了磨皮与提亮，未覆盖液化、换脸等更强的编辑。
- 文本种子集中，`ai_written=false` 的条目由项目方代写，存在标签噪声，正式评测前应替换为真实手写内容。
